--------------------------------------------------------------------------------
1. WHAT A2 TESTS
--------------------------------------------------------------------------------

A2 is one of the seven DAG-topology gaps listed in future_experiments.txt.
It tests applyMultiConsumerOptimization's dedup cache HIT path -- when
two consumers of the same producer share the same (OperationName,
ResultType) cache key. Until A2 nothing in the suite exercised this
code path -- only the cache-miss / cache-with-distinct-keys paths.

Predicted pass behavior: when two truncf-fp16 consumers of a fp32 cat
arrive, the cache misses on the first (builds new chain) and HITS on
the second (reuses chain). The pass must produce ONE rewritten
cat-on-fp16, NOT two.


--------------------------------------------------------------------------------
2. CONSTRUCTION FINDING
--------------------------------------------------------------------------------

The textbook A2 pattern -- one fp32 tt.cat consumed by two
`c.to(tl.float16)` calls -- does NOT reach the cache-hit code path
in DowncastReorderOptimizer on real Triton. The frontend / canonicalize step
folds the two identical `arith.truncf %c` ops into ONE SSA value
BEFORE our pass runs, so the pass sees only ONE consumer of the cat
and the cache stores a single entry. The lookup never gets to hit.

To actually drive the cache-hit path we insert an additional mover
layer (a reshape) between cat and each truncf, with DIFFERENT output
shapes so the frontend cannot merge them. The pass then propagates
each truncf up through its reshape, and only at cat do the two
cloned truncf clones meet -- with identical (OperationName,
ResultType) but distinct SSA values. The cache misses on the first
and HITS on the second.

Kernel pattern:

   load a (fp32)         load b (fp32)
       |                       |
   reshape                  reshape
       \\__________ cat ________/                <- fp32 cat
                    |
        +-----------+-----------+
        |                       |
   reshape (2BM,BN)        reshape (BM,2BN)      <- different shapes,
        |                       |                   prevents frontend CSE
     truncf-fp16            truncf-fp16            <- two truncf-fp16 ops
        |                       |                    same kind+type,
     reshape (2BM,BN)       reshape (2BM,BN)         different operands
        |                       |
     store fp16              store fp16


--------------------------------------------------------------------------------
3. STRUCTURAL PROOF (TTIR)
--------------------------------------------------------------------------------

OFF TTIR:
  %c    = tt.cat %a_flat, %b_flat : tensor<16384xf32> -> tensor<32768xf32>
  %c_r1 = tt.reshape %c : tensor<32768xf32> -> tensor<256x128xf32>
  %c_r2 = tt.reshape %c : tensor<32768xf32> -> tensor<128x256xf32>
  %d1   = arith.truncf %c_r1 : tensor<256x128xf32> to tensor<256x128xf16>
  %d2   = arith.truncf %c_r2 : tensor<128x256xf32> to tensor<128x256xf16>
  -- TWO truncfs, distinct operands

ON TTIR:
  %d1    = arith.truncf %a_19 : tensor<128x128xf32> to tensor<128x128xf16>
  %d1_24 = arith.truncf %b_23 : tensor<128x128xf32> to tensor<128x128xf16>
  %c     = tt.cat %a_flat, %b_flat : tensor<16384xf16> -> tensor<32768xf16>
                                                                       ^^^^^
  -- exactly ONE cat-on-fp16 (the cache hit produced one shared chain
     consumed by both downstream reshapes c_r1 / c_r2)

CACHE-HIT PATH VERIFIED for the first time in the suite.


--------------------------------------------------------------------------------
4. BIT-EXACT VERIFICATION
--------------------------------------------------------------------------------

verify_all.sh ran A2 OFF and ON at (M, N, BM, BN) = (2048, 2048, 128, 128).
Both outputs (out1, out2) bit-identical across OFF/ON. Combined SHA-256
matches.

--------------------------------------------------------------------------------
8. WHAT A2 ADDS TO THE STORY
--------------------------------------------------------------------------------

  - First empirical verification of the cache HIT code path. The path
    is reachable only through multi-level chain propagation (cloned
    reducers meeting at the producer), not via naive textually-
    duplicated reducers (the frontend pre-merges those).
  - Documents the surprising finding that the textbook A2 pattern
    fails to reach the cache hit code path on real Triton.
  - 1.22x speedup at the canonical 128x128 tile, 72% DRAM-explained.
