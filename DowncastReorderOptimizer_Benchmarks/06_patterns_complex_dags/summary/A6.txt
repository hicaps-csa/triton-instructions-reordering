--------------------------------------------------------------------------------
1. WHAT A6 TESTS
--------------------------------------------------------------------------------

A6 is one of the seven DAG-topology gaps in future_experiments.txt.
It tests the per-operand bitwidth guard in eligibleReducers
(DowncastReorderOptimizer.cpp lines 356-372), which skips the consumer when ANY
producer operand's element-type bitwidth is NOT STRICTLY GREATER than
the consumer's destination bitwidth:

    elemTy.getIntOrFloatBitWidth() <= dstType.getElementTypeBitWidth()
        -> allOperandsReduce = false; break;

A6 as originally framed (cat of mixed-bitwidth operands) cannot be
expressed in Triton because all cat operands must share a dtype.
Instead we test the same guard via a single-operand mover (reshape)
with an operand whose bitwidth EQUALS the destination -- the boundary
case `width <= dst_width`.


--------------------------------------------------------------------------------
2. TWO PATHS IN ONE KERNEL
--------------------------------------------------------------------------------

Path A (guard FAILS):
  load fp16 -> reshape (mover, 16-bit) -> fptosi -> i16 (16-bit)
  Operand bitwidth 16 == dest 16. Strictly-greater check FAILS.
  -> Pass SHOULD NOT rewrite. Expect ON IR identical to OFF IR for
     this chain.

Path B (guard PASSES, control case):
  load fp32 -> reshape (mover, 32-bit) -> fptosi -> i16 (16-bit)
  Operand bitwidth 32 > 16. Guard PASSES.
  -> Pass SHOULD rewrite. Expect ON IR with fptosi pushed above
     reshape on this chain.

Both paths run in the same kernel and produce i16 stores. The TTIR
diff between OFF and ON should show ONE rewrite (Path B), not two.


--------------------------------------------------------------------------------
3. STRUCTURAL PROOF (TTIR)
--------------------------------------------------------------------------------

OFF TTIR (both paths):
  Path A:  %a16_flat = tt.reshape %a16 : f16 -> f16
           %pa = arith.fptosi %a16_flat to i16
  Path B:  %a32_flat = tt.reshape %a32 : f32 -> f32
           %pb = arith.fptosi %a32_flat to i16

ON TTIR:
  Path A:  %a16_flat = tt.reshape %a16 : f16 -> f16    -- UNCHANGED
           %pa = arith.fptosi %a16_flat to i16          -- guard correctly fails

  Path B:  %pb = arith.fptosi %a32 to 128x128xi16       -- REWRITTEN
           %a32_flat = tt.reshape %pb : 128x128xi16 -> 16384xi16
                                                       -- fptosi pushed ABOVE reshape

The two paths in the SAME kernel give a single-shot proof that the
guard fires SELECTIVELY: same-bitwidth operands skipped, strictly-
greater operands rewritten.


--------------------------------------------------------------------------------
4. BIT-EXACT VERIFICATION
--------------------------------------------------------------------------------

Both outputs (pathA, pathB) bit-identical across OFF/ON. SHA-256 match.

--------------------------------------------------------------------------------
7. WHAT A6 ADDS TO THE STORY
--------------------------------------------------------------------------------

  - First test of the per-operand bitwidth guard's SKIP behavior.
  - "Negative-control" experiment: demonstrates that the pass is a
    perf no-op when the guard correctly skips a non-eligible
    consumer.
  - Two paths in one kernel give simultaneous proof that the guard
    fires selectively at the consumer level, not at the producer
    level.
  - The original A6 spec (cat of mixed-bitwidth operands) cannot be
    expressed in Triton because cat operands must share a dtype.
    Reframed to use single-operand movers (reshape) with same-vs-
    greater bitwidth.
